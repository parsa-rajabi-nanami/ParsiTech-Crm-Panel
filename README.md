# ParsiReach — اتوماسیون بازاریابی ووکامرس

**نسخه ۲.۰.۰** — بازطراحی‌شده بر پایه افزونه قبلی ParsiShop CRM

ParsiReach یک افزونه اتوماسیون پیامکی برای فروشگاه‌های WooCommerce است. به‌جای ارسال دستی پیام، می‌توانید بر اساس تغییر وضعیت سفارش، پیامک‌های زمان‌بندی‌شده و تکرارشونده بسازید و برای هر اتوماسیون شرط مبلغ سفارش و سقف تعداد پیام تعیین کنید.

## قابلیت‌ها

- اتصال به API فعلی IPPanel Edge برای پیامک متنی و پترن تأییدشده.
- ساخت اتوماسیون بر اساس وضعیت سفارش: در حال انجام، تکمیل‌شده یا در انتظار بررسی.
- تعیین تأخیر شروع، تعداد تکرار و فاصله زمانی بین پیام‌ها.
- شرط حداقل/حداکثر مبلغ سفارش و سقف ارسال برای هر شماره در بازه زمانی.
- توکن‌های پویا مانند نام مشتری، شماره سفارش، مبلغ سفارش و نام محصول.
- بازه مجاز ارسال با پشتیبانی از بازه‌های شبانه‌روزی (مانند ۲۱ تا ۷).
- صف ارسال، جلوگیری از اجرای تکراری یک کار، تلاش مجدد برای خطاهای موقت و امکان توقف/ادامه اتوماسیون.
- حالت Sandbox برای آزمودن قوانین و زمان‌بندی بدون ارسال واقعی.
- ثبت رضایت بازاریابی، رعایت لغو اشتراک و ثبت لاگ با شماره ماسک‌شده.
- داشبورد، گزارش‌ها، فیلتر وضعیت و شماره و تلاش مجدد برای ارسال ناموفق.
- پشتیبانی از HPOS ووکامرس.

## پیش‌نیازها

- WordPress 6.4 یا بالاتر
- PHP 8.1 یا بالاتر
- WooCommerce 7.9 یا بالاتر
- افزونه فعال WooCommerce
- کلید API و شماره فرستنده معتبر در پنل IPPanel Edge

## نصب و راه‌اندازی

1. قبل از جایگزینی نسخه قبلی، از فایل‌ها و دیتابیس سایت نسخه پشتیبان بگیرید.
2. ZIP را از مسیر افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه نصب کنید. اگر نسخه قبلی با نام پوشه `parsishop-crm` نصب است، ZIP جدید را به‌صورت جایگزینی/به‌روزرسانی همان افزونه نصب کنید و دو نسخه را هم‌زمان نگه ندارید.
3. از منوی **ParsiReach ← تنظیمات پیامک**، کلید API و شماره فرستنده را وارد و ذخیره کنید. شماره فرستنده باید خط مجاز پنل باشد و به قالب E.164 تبدیل شود؛ برای خط‌های ایران مانند `+983000505` وارد کنید.
4. دکمه «تست اتصال و استعلام اعتبار» ارتباط با پنل را بررسی می‌کند؛ این عملیات پیامک ارسال نمی‌کند.
5. سرویس را فعال نگه دارید و **حالت Sandbox** را روشن بگذارید. در این حالت اجرای اتوماسیون‌ها فقط در لاگ شبیه‌سازی ثبت می‌شود و پیامکی به گیرنده ارسال نمی‌شود.
6. برای ثبت رضایت، گزینه نمایش چک‌باکس اختیاری را فعال کنید. این چک‌باکس در تسویه‌حساب کلاسیک ووکامرس بدون تیک پیش‌فرض نمایش داده می‌شود. فقط مشتریانی که آگاهانه آن را انتخاب کنند به فهرست رضایت پیامکی افزوده می‌شوند.
7. در بخش **اتوماسیون‌ها** یک قانون بسازید. نمونه: رویداد «سفارش تکمیل‌شده»، تأخیر ۳ روز، متن «سلام {customer_name}، از خرید شما سپاسگزاریم…».
8. گزارش‌ها و صف را بررسی کنید. پس از اطمینان از متن، شماره فرستنده، شرایط و رضایت‌ها، Sandbox را خاموش کنید تا API واقعی استفاده شود.

> خاموش‌کردن Sandbox و ارسال تست پیامک می‌تواند پیام واقعی و هزینه‌دار ارسال کند. ابتدا شماره مقصد تست را بررسی کنید.

## رضایت و لغو اشتراک

- الزام رضایت بازاریابی به‌صورت پیش‌فرض روشن است. مشتریان قدیمی که سابقه رضایت ندارند تا زمان ثبت رضایت صریح پیام بازاریابی دریافت نمی‌کنند.
- چک‌باکس رضایت اختیاری و بدون انتخاب پیش‌فرض است.
- فهرست لغو اشتراک پیش از ارسال بررسی می‌شود. پیام متنی عادی می‌تواند لینک لغو اشتراک امضاشده داشته باشد.
- در پترن تأییدشده، امکان الحاق خودکار متن پس از تأیید پترن وجود ندارد؛ عبارت لغو اشتراک یا متغیر لینک آن باید در خود پترن و مطابق قواعد پنل تعریف شده باشد.
- این امکانات ابزار فنی هستند و به‌تنهایی تضمین‌کننده انطباق حقوقی کسب‌وکار با قوانین محلی یا مقررات حریم خصوصی نیستند. متن رضایت، سیاست نگهداری و روش لغو اشتراک باید با مقررات محل فعالیت شما هماهنگ شود.

## توکن‌های پیام

برای پیامک متنی یا مقدارهای پترن می‌توانید از این توکن‌ها استفاده کنید:

- `{customer_name}` و `{customer_last_name}`
- `{order_number}`، `{order_date}` و `{order_total}`
- `{product_name}` و `{shop_name}`
- `{unsubscribe_url}`

در حالت پترن، مقدارها باید به‌صورت JSON object و با کلیدهایی منطبق بر متغیرهای پترن تأییدشده وارد شوند؛ برای نمونه:

```json
{
  "customer_name": "{customer_name}",
  "order_number": "{order_number}",
  "unsubscribe_url": "{unsubscribe_url}"
}
```

## رفتار ارسال و گزارش‌ها

- وضعیت «ثبت ارسال در پنل» به معنی پذیرش درخواست توسط وب‌سرویس است، نه تأیید تحویل پیامک به گوشی. در این نسخه دریافت و پردازش Delivery Receipt پیاده‌سازی نشده است.
- خطاهای موقت شبکه و محدودیت نرخ تا حداکثر سه تلاش با فاصله افزایشی دوباره امتحان می‌شوند.
- پیام‌های خارج از بازه مجاز به شروع بازه بعدی منتقل می‌شوند.
- تکرارهای Sandbox در سقف دفعات ارسال واقعی محاسبه نمی‌شوند.
- زمان‌بندی از Action Scheduler ووکامرس استفاده می‌کند و در نبود آن به WP-Cron برمی‌گردد. برای فروشگاه پرترافیک، فعال‌بودن WP-Cron واقعی/سیستم‌کران توصیه می‌شود.

## محدوده نسخه ۲.۰

این محصول در نسخه فعلی **اتوماسیون پیامکی مبتنی بر رویداد سفارش** است؛ ابزار ارسال انبوه خبرنامه، مدیریت کمپین ایمیلی، بازیابی سبد خرید رهاشده یا CRM کامل مخاطبین نیست.

صفحه قدیمی ایمیل فقط پیش‌نویس ذخیره می‌کرد و موتور ارسال، صف، رضایت و لغو اشتراک قابل اتکایی نداشت؛ به همین دلیل از رابط فعال حذف شده است. جدول‌های قدیمی ایمیل برای جلوگیری از حذف ناخواسته داده‌های نسخه قبلی حفظ شده‌اند، اما در نسخه ۲.۰ قابلیت ارسال ایمیل ارائه نمی‌شود.

چک‌باکس رضایت فعلاً برای **Checkout کلاسیک** ووکامرس پیاده‌سازی شده است؛ سازگاری رابط Checkout Blocks ادعا نمی‌شود. شماره‌های موبایل ایران با الگوی `09xxxxxxxxx` پشتیبانی می‌شوند.

## داده‌ها، ارتقا و حذف افزونه

- نام فنی پوشه، optionها، جدول‌ها و hookهای زمان‌بندی‌شده قدیمی برای ارتقای درجا و حفظ داده‌ها نگه داشته شده‌اند؛ نام نمایشی افزونه ParsiReach است.
- ارتقا، جدول ثبت رضایت را اضافه می‌کند و جدول‌ها و اتوماسیون‌های قبلی را حذف نمی‌کند.
- کلید API به کمک Sodium یا AES-256-GCM و بر پایه WordPress salts رمزنگاری می‌شود. تغییر کلیدهای salt در `wp-config.php` می‌تواند مانع رمزگشایی کلید ذخیره‌شده شود؛ قبل از چنین تغییری کلید API را در پنل افزونه دوباره ذخیره کنید.
- با حذف افزونه، تنظیمات اتصال و زمان‌بندی‌ها حذف می‌شوند؛ جدول‌ها، لاگ‌ها، رضایت‌ها و فهرست لغو اشتراک عمداً باقی می‌مانند تا حذف اشتباهی باعث از دست رفتن سوابق نشود. پاک‌سازی کامل داده‌ها در این نسخه ابزار مدیریتی اختصاصی ندارد.
